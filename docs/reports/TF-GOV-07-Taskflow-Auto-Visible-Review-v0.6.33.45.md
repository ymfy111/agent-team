# TF-GOV-07｜taskflow 自动推进与低打扰可见输出评审报告

> 基线：v0.6.33.45 / TF-P0B-05  
> 对应 skill：taskflow v0.9.16  
> 结论：PASS

## 1. 背景

上一轮检查点模式证明了主对话正文可见性，但也暴露出长程任务体验问题：用户不应为了无风险普通节点反复点击“继续”。本轮将 taskflow 默认目标修正为：低打扰或无人值守推进整个任务流，同时保留每个节点 start/done 的主对话正文过程输出。

## 2. 修正内容

1. `taskflow` 升级到 v0.9.16。
2. 明确默认模式为 auto-visible mode：用户确认后自动推进，不逐节点等待继续。
3. 检查点模式降级为测试/降级/人工验收专用。
4. 普通节点只输出简洁 start/done；7 列进度表默认放在阶段/最终总结。
5. 长节点超时、用户询问进度、风险/阻塞时才中途推送阶段性 7 列表格。
6. `tools/taskflow/taskflow.mjs start/fail` 不再自动追加完整 progress 表，避免普通节点产生多余中途表格。
7. 同步更新 SKILL、README、技能包总 README、治理指南、导航和 CHANGELOG。

## 3. 验证

| 检查项 | 结果 | 说明 |
|---|---|---|
| `node --check tools/taskflow/taskflow.mjs` | PASS | 脚本语法通过 |
| skill 版本同步 | PASS | SKILL / README / skills-README 均为 v0.9.16 |
| 默认执行模式 | PASS | 已明确 auto-visible mode 为默认 |
| 检查点模式边界 | PASS | 已明确仅作为测试/降级/人工验收专用 |
| 中途表格规则 | PASS | 已明确普通节点不插表，长节点/用户询问/风险才推送 |
| 工具输出 | PASS | start/fail 不再自动附加 7 列 progress 表 |

## 4. 风险与边界

当前 ChatGPT 单轮对话环境不一定支持在同一轮执行中推送多条真正的普通助手消息。因此，真实无人值守 + 过程实时可见需要上层 runner / 调度器具备消息推送能力。skill 层已经定义目标行为和降级策略。

## 5. 结论

本轮修正满足用户目标：长程任务默认低打扰自动推进，过程输出应像检查点测试那样完整可见，但不要求用户无意义介入。
