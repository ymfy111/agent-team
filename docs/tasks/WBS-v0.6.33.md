## 0. 本次任务拆解原则

```text
1. 第一阶段优先落地主智能体维护任务清单。
2. 任务文档使用结构化 Markdown。
3. 程序只读取和更新它关心的元数据与标记区块。
4. 状态机只做轻量约束，成熟后再演进。
5. Runtime 编排放在后期，不作为第一阶段阻塞项。
```

## J 组：task/taskflow v0.4.1 机制产品化预研任务

### J-01：SOW 选择与工作包建模

- 目标：支持在任务流生成前确认本轮工作包范围。
- 产物：SOW / WorkPackage 数据结构草案。
- 验收：能区分“本轮执行范围”和“项目长期待办”。

### J-02：任务单颗粒度规则

- 目标：制定任务单拆分标准，避免任务过碎或过粗。
- 产物：任务拆分规则与示例。
- 验收：简单编辑、单次截图、单文件小修不单独成为任务单。

### J-03：暂停 / 恢复 / 退出状态

- 目标：把 taskflow 暂停机制映射为产品级待决策、阻塞和退出。
- 产物：状态字段、恢复规则、用户提示模板。
- 验收：暂停后能从原任务恢复，退出时能说明原因和建议。

### J-04：真实计时与进度记录

- 目标：任务耗时来自执行记录，而不是智能体口头估算。
- 产物：TaskEvent 时间字段、节点开始/完成事件。
- 验收：无法计时时明确标注，不输出无依据耗时。

### J-05：单任务与任务流输出边界

- 目标：区分单任务执行和任务流编排，避免 UI 与执行记录混乱。
- 产物：单任务视图 / 任务流视图边界说明。
- 验收：单任务不显示任务流进度图，任务流才显示跨节点进度。
