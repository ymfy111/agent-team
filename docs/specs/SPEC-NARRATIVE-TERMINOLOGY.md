# 产品叙事术语基线

> 用途：统一对外材料（PPT、官网、宣传图、话术）中"两类数字员工"相关的命名与口号口径，避免多人刷材料时混搭、漂移。
> 适用范围：对外叙事与营销文案。**不约束代码与技术名词**（见末节"边界"）。

## 1. 主口号（定稿）

```text
两类数字员工
一类把业务建起来，一类把业务跑起来
```

- 用"**类**"不用"个"：后续叙事会出现多个建造型实例、多个运营型实例，"类"与之一致；"个"会与后文自相矛盾。
- "建起来 / 跑起来"对仗，保持口语与节奏。

## 2. 角色命名（定稿）

| 角色 | 定稿名 | 一句话定位 | 三能力 | 产出 |
|---|---|---|---|---|
| 建造侧 | **建造型** | 把业务建出来 | 理解业务 · 建模生成 · 构建应用 | 应用 + 智能体 |
| 运营侧 | **运营型** | 把业务跑起来 | 执行任务 · 人机协同 · 监控优化 | 业务结果 + 运行沉淀 |

- 角色名只保留中文，**去掉英文 Build / Run 后缀**。
- 两名必须成对出现：建造型 ⇄ 运营型，禁止"建造型 vs 运行型"混搭。

## 3. 配套文案（定稿）

| 位置 | 定稿文案 |
|---|---|
| 顶部小字 | 数字员工操作系统(DEOS)，建造并运营 ↓ |
| 副标题 | 以业务本体为核心，从建造到运营，闭环自进化 |
| 上行·左→中 | 建造沉淀　把成果建进本体 |
| 上行·中→右 | 能力驱动　本体把能力交给运营侧 |
| 下行·右→中 | 运营反馈，越跑越准 |
| 下行·中→左 | 本体供养　基于本体建模 · 复用语义编排智能体 |
| 业务本体（中心） | 业务本体 · 语义·关系·规则·指标·数据·流程 · 越跑越准的业务大脑 |
| 底部金句 | 别人交付一个 AI 工具，我们交付**两类**永不下班、越用越懂你业务的数字员工 |

> 产品系统名以「数字员工操作系统（DEOS）」为准（与 `SDD-DEOS-ARCHITECTURE-v0.7.md`、`PRD-v0.7.md` 一致）；旧称「智能业务操作系统(BOS)」停用。叙事角色名「建造型 / 运营型」保持不变（技术口径「构建型 / 应用型」对照见架构总纲附录 A）。

## 4. 全局替换对照表（刷材料用）

| 旧表述 | 新表述 |
|---|---|
| 生成型 / 生成型·Build | 建造型 |
| 运行型 / 运行型·Run | 运营型 |
| 两个数字员工 | 两类数字员工 |
| 一个把业务建出来 | 一类把业务建起来 |
| 一个把业务跑起来 | 一类把业务跑起来 |
| 生成沉淀 | 建造沉淀 |
| 从生成到运行 | 从建造到运营 |
| （主标题）生成并运行 | 建造并运营 |
| 智能业务操作系统 / BOS | 数字员工操作系统 / DEOS |

## 5. 边界：哪些"生成/运行"不改

仅当作为**数字员工角色名**时才替换。以下属产品固有技术名词，**保留不改**：

- 运行态、运行网关、运行时、RuntimeGateway
- 泛指"AI 生成内容/生成层"的"生成"（如 SDD-GENERATION-LAYER 中的生成层）

> 刷材料口诀：**改"型"不改"层"，改角色名不改技术词。**
