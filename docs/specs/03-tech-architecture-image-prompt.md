## 2. 架构内容说明

### 2.1 中心区

**中心控制面 — Runtime Gateway 运行网关**

- Device 注册 / 注销 / 心跳汇总，维护全局 Device 状态视图。
- 向 Device 下发沙箱启停 / 配置指令。
- Device 离线时触发孤儿任务回收。
- ServiceRouting 服务路由（发现可调用能力 endpoint）。
- **关键边界：不做 TaskDispatch 任务派发**——任务派发由各 Device 的 Scheduler 本地完成。

**中心基础设施（共享）**

- PostgreSQL：唯一事实源，含任务表、服务注册表、运行账本。
- NATS JetStream：事件总线，承载两条流——① 内部调度信号（加速派发）；② RuntimeEvent（必达，对外审计 / 运营）。
- Redis：热状态、分布式锁、限流。

### 2.2 分布式 Device 区

每台 Device 自上而下包含：

- Sandbox Daemon：沙箱守护，负责启停 / 配置沙箱、心跳上报网关，向 Scheduler 提供本机 DE 列表。
- Scheduler：任务调度，订阅 NATS（快路径）+ 轮询 PG（兜底）、CAS 原子领取任务、送达本机沙箱、Checkpoint 超时巡检。
- LiteLLM：本机模型网关，token 计量 / 配额。
- DE 沙箱 ×N：数字员工实例（规划 / 执行 / 测试等角色）。

### 2.3 安全红线

- DE 沙箱无 PG 直连凭据，只能走 REST API（图中 DE 沙箱标注 ⚠，与 Scheduler 间走灰色 REST 线）。
- PG 凭据只给 Scheduler / API 服务。

### 2.4 任务派发闭环

规划岗 DE 写 PG 任务表（权威）+ 发 NATS 信号（加速）→ 各 Device Scheduler 按 `target_policy` 认领本机数字员工的任务 → 送达沙箱执行 → 回写 PG → 触发依赖解除。

## 3. 箭头颜色规则

- 橙色：注册 / 心跳 / 控制指令（Device ↔ Gateway）
- 蓝色：任务读写（Scheduler ↔ PG，SQL / REST）
- 紫色：NATS 调度信号（Scheduler 订阅，加速派发）
- 绿色：模型调用（DE 沙箱 ↔ 本机 LiteLLM）
- 灰色虚线：领任务 / 回写结果（DE 沙箱 ↔ Scheduler，走 REST API）/ 状态同步 / 审计
