# 文档导航

> 本文件是 `agent-team` / 智能软件工厂项目的 docs 统一入口。  
> 新会话、新智能体或人工接手时，应先读本文档，再按“主规格 → 计划 → 工作项 → 规范/模板 → 原型/报告”的顺序阅读。

---

## 1. 当前文档体系口径

### 1.1 用户侧与设计侧命名

| 用户侧 | 设计侧 | 说明 |
|---|---|---|
| 计划 | Plan | 项目级目标、路线图、阶段规划。 |
| 阶段 | Stage | 计划下的一段目标区间。 |
| 工作项 | WorkItem | 阶段下的工作组织单元，承载一组相关任务。 |
| 任务 | TaskFlow | 一次可执行任务流，可审计、可验证、可恢复。 |
| 步骤 | TaskTicket | 任务中的最小执行节点，也可理解为 Todo / Node。 |

### 1.2 目录职责

| 目录 | 职责 |
|---|---|
| `docs/specs/` | 主需求、主设计、部署设计、专项设计和子设计。 |
| `docs/plans/` | 计划、阶段、路线图。 |
| `docs/workitems/` | 工作项文档；每个主文档对应一个 WorkItem。 |
| `docs/workitems/runs/` | 任务执行记录；记录 TaskFlow 的步骤、事件、证据和审计。 |
| `docs/reports/` | 评审、验证、复盘报告。 |
| `docs/guides/` | 文档规范、执行治理、Markdown 契约等方法说明。 |
| `docs/templates/` | 可复用模板；不是项目事实源。 |
| `docs/recs/` | 产品化建议、演进建议。 |
| `docs/prototypes/` | 原型归档和图片资源。 |
| `docs/changes/` | 变更记录。 |

## 6. 文档维护规则

1. 新增文档前先读 `GUIDE-DOC-DRIVEN-DEVELOPMENT.md`。
2. 计划文档放 `docs/plans/`；工作项文档放 `docs/workitems/`。
3. 任务执行记录放 `docs/workitems/runs/`；评审与复盘放 `docs/reports/`。
4. 模板统一放 `docs/templates/`，实际文档按类型放入对应目录。
5. 每次调整 docs 结构或关键命名，必须同步 `文档导航.md`、`project-memory.md` 和 `CHANGELOG-v0.6.33.md`。
6. 原型归档和图片资源属于基础资产，不应被清理。
7. 已完成任务的运行记录和评审报告若结论已沉淀，可清理；但主规格、模板、原型、指南和当前工作项不得清理。
