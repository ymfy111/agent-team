## 1. 当前核心结论

智能软件工厂的核心不是智能体对话，而是围绕 `TaskFlow / TaskTicket` 组织计划、执行、协作、验证、评审和交付。

当前项目自身就是一个智能软件工厂雏形：

```text
Project
  → Stage / Plan
    → WorkPackage / TaskFlowGroup
      → TaskFlow
        → TaskTicket / Node
          → Artifact / Evidence / Review / Decision / Handoff
```

当前文档目录与产品对象的对应关系：

| 目录 | 产品化语义 | 用途 |
|---|---|---|
| `docs/plans/` | Stage / Plan | 阶段目标、路线图、能力路线；回答“为什么做、按什么阶段做”。 |
| `docs/tasks/` | WorkPackage / TaskFlowGroup | 一组有序 TaskFlow 的工作包清单；维护状态、当前焦点、能力摘要和下一步。 |
| `docs/tasks/runs/` | TaskFlow Run | 单次 TaskFlow 执行记录目录；本次收尾后历史 run 已清理，后续仅保留当前/必要运行记录。 |
| `docs/specs/` | Product / System / Sub-design | 产品、系统、专项设计。 |
| `docs/reports/` | ReviewRecord / QA / 复盘 | 评审、验证、复盘报告目录；本次收尾后历史测试/过程报告已沉淀到通用文档并清理。 |
| `docs/recommendations/` | Product Recommendations | 产品化建议、组织协同建议。 |
| `docs/guides/` | 方法与执行规则 | taskflow 治理、Guarded Flow、Markdown 契约等当前有效指南。 |
| `docs/templates/` | 文档化模板 | 结构化 Markdown 模板。 |
| `docs/changes/` | ChangeLog | 变更记录。 |


说明：

- `docs/tasks/` 下的主文档默认不是零散单任务，而是 WorkPackage / TaskFlowGroup。
- 一个 WorkPackage 文档可以维护一组有序 TaskFlow，例如 `TF-GF-IMPL` 包含 `01/02/03/04`。
- 单次执行记录默认进入 `docs/tasks/runs/`，但已完成任务的过程记录如果没有长期复用价值，可以在结论沉淀后清理。
- 评审、验证、复盘报告默认进入 `docs/reports/`，但已沉淀到指南、路线图、设计或工作包文档的历史报告不长期保留。
- `docs/plans/` 只管理阶段目标和路线图，不直接管理所有子 TaskFlow。

## 5. 本次收尾清理原则

本次 docs 包进行了瘦身清理，原则如下：

1. 保留当前事实源、当前路线图、当前设计、当前工作包和通用指南。
2. 删除已被新文档替代的历史任务建议、补丁文件、旧版本治理指南。
3. 删除已完成任务的过程性 run / report；有复用价值的内容已沉淀到路线图、工作包、指南、模板或子设计。
4. 保留 `docs/tasks/runs/` 与 `docs/reports/` 目录语义，供后续当前任务或必要审计继续使用。
5. 后续新增任务完成后，应优先把可复用经验沉淀到通用文档，再决定是否保留原始运行记录。

## 6. 目录维护规则

1. 新增阶段路线、能力路线、项目计划：放入 `docs/plans/`。
2. 新增工作包 / 任务流组：放入 `docs/tasks/`，建议命名为 `TF-<AREA>-<GROUP>-vX.md`。
3. 单次 TaskFlow 运行记录：放入 `docs/tasks/runs/`，完成并沉淀后可清理。
4. 评审、验证、复盘报告：放入 `docs/reports/`，完成并沉淀后可清理。
5. 产品、系统、对象模型、专项设计：放入 `docs/specs/`。
6. 结构化模板：放入 `docs/templates/`。
7. 每次 docs 包更新必须同步本文件和 `docs/project-memory.md`。
8. 不要为保留历史而堆积文档；已完成事项若有复用价值，应沉淀到通用文档，原始过程文件可不保留。
