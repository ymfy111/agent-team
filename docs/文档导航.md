## 1. 当前核心结论

智能软件工厂的核心不是智能体对话，而是围绕 `TaskFlow / TaskTicket` 组织计划、执行、协作、验证、评审和交付。

当前项目 `agent-team` 是智能软件工厂的一个简化雏形：

```text
Project
  → Stage / Plan
    → WorkPackage / TaskFlowGroup
      → TaskFlow
        → TaskTicket / Node
          → Artifact / Evidence / Review / Decision / Handoff
```

目录与产品对象的对应关系：

| 目录 | 产品化语义 | 用途 |
|---|---|---|
| `docs/specs/` | Product / System / Sub-design | 主需求、主设计、部署设计、专项设计。 |
| `docs/plans/` | Stage / Plan | 阶段目标、路线图、能力路线。 |
| `docs/tasks/` | WorkPackage / TaskFlowGroup | 一组有序 TaskFlow 的工作包清单，维护状态、当前焦点和下一步。 |
| `docs/tasks/runs/` | TaskFlow Run | 单次 TaskFlow 执行记录目录，按需保留。 |
| `docs/reports/` | ReviewRecord / QA / 复盘 | 评审、验证、复盘报告目录，按需保留。 |
| `docs/recs/` | Product Recommendations | 产品化建议、组织协同建议。 |
| `docs/guides/` | 方法与执行规则 | taskflow 治理、Guarded Flow、Markdown 契约等当前有效指南。 |
| `docs/templates/` | 文档化模板 | 计划、任务、任务流、决策、评审等结构化 Markdown 模板。 |
| `docs/prototypes/` | Prototype Archive | 当前原型归档和 `pic/` 图片资源。 |
| `docs/changes/` | ChangeLog | 阶段变更记录。 |

## 8. 目录维护规则

1. 主需求、主设计、部署设计、专项设计放入 `docs/specs/`；主 PRD / SDD 不应被子设计替代或清理。
2. 阶段路线、能力路线、项目计划放入 `docs/plans/`，文件名建议使用 `PLAN-` 前缀体现类型与主子关系。
3. `docs/tasks/` 下主文档默认是 WorkPackage / TaskFlowGroup，可管理一组有序 TaskFlow；单次执行记录放入 `docs/tasks/runs/`。
4. 产品化建议放入 `docs/recs/`，文件名使用 `REC-` 前缀。
5. 通用模板放入 `docs/templates/`，不作为过程性文件清理。
6. 当前原型归档和 `pic/` 资源放入 `docs/prototypes/`，随 docs 全量包同步。
7. 已完成任务的 run / report / 测试记录不默认长期保留；有复用价值的信息应沉淀到指南、模板、路线图、工作包或子设计。
8. 每次 docs 包更新必须同步本文件和 `docs/project-memory.md`。
