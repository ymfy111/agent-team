## 本轮核心架构口径

```text
1. 当前阶段不要直接实现完整复杂状态机，避免过度设计。
2. 第一阶段采用 Agent-led Task List：协同规划岗 / 主智能体负责生成计划、拆任务、维护任务清单。
3. 系统负责持久化计划、任务单、执行反馈、审查记录和待决策事项。
4. 主子智能体可以通讯，但通讯结果必须回写为 TaskEvent、ExecutionResult、ReviewRecord 或 DecisionItem。
5. Markdown 继续作为人和智能体友好的协作格式，但要升级为“结构化 Markdown”。
6. 结构化 Markdown = YAML Front Matter + Markdown 正文 + 标记区块 + 可选 JSONL 事件记录。
7. 后续按四阶段演进：Agent-led Task List → Guarded Task Flow → State-machine Orchestration → Factory Runtime Orchestration。
8. 后续交付执行默认采用 task / 任务执行 v0.3：任务执行为标准模式，任务执行 高质量为高质量模式。
9. 长程任务编排可采用 taskflow / 任务流执行 v0.2：taskflow 调用 task(managed)，支持暂停、恢复、退出和耗时复盘。
10. taskflow 是单智能体串行任务流参考；智能工厂是多智能体协同系统，后续需要并行调度、资源占用、冲突检测和 Runtime 状态同步。
```

## 目录使用规则

- `docs/specs/`：正式需求、系统设计、专项集成方案、P0a 施工图、Mock 数据设计。
- `docs/plans/`：阶段计划、路线图、开发计划。
- `docs/tasks/`：编程智能体可执行任务清单、任务单、WBS。
- `docs/templates/`：结构化计划、任务、审查、待决策等 Markdown 模板。
- `docs/collab/`：设计智能体、编程智能体、评审智能体的分工与工作指南。
- `docs/decisions/`：ADR / 架构决策 / 产品关键决策。
- `docs/changes/`：版本变更说明与 Changelog。
- `docs/reports/`：评审报告、走查报告、测试报告。
- `docs/prototypes/`：HTML 原型与视觉资源；最新原型可位于交付包根目录的 `prototypes/`。
- `docs/references/`：外部项目参考资料；采纳后需转化为 specs 或 ADR。
- `docs/guides/`：协作方法、文档规范、操作指南、task / taskflow / stable-delivery 等执行流程说明。

## 维护约定

1. 新增文档必须归类到以上目录，并在本文件中补充对应入口。
2. 阶段状态发生变化时，及时更新阶段总览表格。
3. 原型文件版本化保存，不覆盖历史版本。
4. 项目事实写入 `docs/project-memory.md`；智能体运行状态写入本地智能体记忆目录。
5. 生成文件包应保持与仓库目录一致，便于本地解压覆盖。
6. 文档文件名优先使用英文缩写，文档标题可以使用中文。
7. 后续打包更新文档时必须包含 `docs/文档导航.md`。
8. 若文档包无法删除旧文件，应在 README 中明确“旧文件清理建议”。
9. v0.6.33.29 是当前原型安全基线；后续文档小修不自动提升原型版本。
