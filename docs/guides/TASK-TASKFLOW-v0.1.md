# task / taskflow 技能实践参考

> 版本：v0.1 参考稿  
> 用途：记录 `task` / `taskflow` 技能经验与智能软件工厂设计理念的对应关系。  
> 注意：本文是设计参考，不代表普通用户界面必须暴露这些术语。

## 1. 技能定位

| 技能 | 中文触发 | 定位 |
|---|---|---|
| task | 任务执行 / 任务执行 高质量 | 单任务质量闭环 |
| taskflow | 任务流执行 / 任务流执行 高质量 | 长程任务清单编排，调用 task |

## 2. 两层机制

```text
taskflow 负责：读任务清单、选下一项、控制顺序、更新状态、阶段汇总。
task 负责：一个任务的计划、执行、验证、评审、修复、交付。
```

## 3. direct / managed 模式

| 模式 | 说明 | 对应产品语义 |
|---|---|---|
| task direct | 用户直接调用任务执行，执行前必须确认计划 | 用户发起单任务 |
| task managed | taskflow 调用 task，不逐项等待用户确认 | 长程任务中的子任务执行 |

## 4. 与智能工厂设计映射

| 技能经验 | 智能工厂映射 |
|---|---|
| taskflow | 协同规划岗 / 主智能体维护任务流 |
| task | 单个 TaskTicket 的质量闭环 |
| managed task | 被编排的无人值守子任务 |
| 暂停门禁 | 待决策、阻塞、质量不收敛 |
| 评审追踪表 | ReviewRecord / QualityGate |
| 前后截图对比 | QA Artifact |
| 任务流进度图 | 项目 / 任务流进度视图 |

## 5. 对产品化的启发

后续智能软件工厂不必一次性实现完整状态机，可以按以下路径演进：

```text
1. 结构化 Markdown 任务流清单。
2. 单任务质量闭环记录。
3. 暂停门禁与待决策映射。
4. 评审追踪与 QA Artifact 持久化。
5. 任务流进度视图。
6. 程序状态机逐步接管常规流转。
```

## 6. UI 边界

普通用户界面不应直接暴露 `taskflow`、`managed`、TaskEvent、状态机等内部术语。UI 应稳定呈现：

```text
项目推进
岗位产出
任务状态
审查意见
待决策
下一步动作
```

底层可从主智能体任务清单逐步演进到程序状态机，用户心智尽量不变。
