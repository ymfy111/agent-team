# task / taskflow 技能实践参考 v0.3

> 本文记录 `task` / `taskflow` 技能对智能软件工厂设计的参考意义。该技能不是最终产品功能，而是当前项目在长程任务执行中的实践样本。

## 1. 技能定位

- `task`：单任务质量闭环，对应一个具体任务的计划、执行、验证、评审、修复和交付。
- `taskflow`：长程任务流编排，读取任务清单，按依赖和状态推进多个 `task`。

## 2. 与智能软件工厂的对应关系

| 技能实践 | 智能软件工厂参考含义 |
|---|---|
| taskflow | 协同规划岗维护任务流 / 任务清单 |
| task(managed) | 长程任务中的子任务无人值守执行 |
| 暂停门禁 | 待决策 / 阻塞 / 需补充信息 |
| 恢复执行 | 用户确认后任务继续流转 |
| 退出机制 | 质量不收敛、依赖缺失、继续风险过高时停止推进 |
| 评审追踪表 | 交付审查与质量门禁证据 |
| 前后截图对比 | UI / 原型类任务的可视化验收证据 |

## 3. 本质区别

`taskflow` 是单智能体依赖技能完成长程串行任务；智能软件工厂是多智能体协同系统，后续需要额外处理并行执行、资源调度、任务冲突、审查队列、运行体状态同步和用户待决策队列。

因此，`taskflow` 只作为轻量运行样式参考，不应直接等同于完整智能工厂。

## 4. 推荐吸收点

1. 开始前先确认流程目标、节点、暂停门禁和产物。
2. 每个具体任务使用 `task` 做质量闭环。
3. 任务执行不下去时进入暂停，而不是静默失败。
4. 暂停必须说明当前位置、原因、已完成节点、未完成节点和需要用户补充的信息。
5. 用户确认后可从暂停点恢复。
6. 完成时输出节点结果、预计/实际耗时对比、评审追踪、产物和下一步建议。

## 5. 不应吸收为当前产品表层的内容

- 不在用户界面暴露 `taskflow`、`task(managed)` 等技能术语。
- 不把普通用户界面改成技能流程界面。
- 不用技能串行流程替代未来多智能体并行编排设计。
