# TASKFLOW-GOVERNANCE v0.9.11

> 文档类型：任务流执行治理指南  
> 适用对象：新会话、新智能体、taskflow skill 维护者  
> 对应 skill：`skills/taskflow/SKILL.md` v0.9.11

## 1. 固定启动节点清单格式

后续任务流启动或恢复执行前，默认使用以下格式，不再因会话变化随意改变。

```text
任务流：TF-XXX｜任务流名称
基线：...
验收模式：委托验收 / 人工验收 / 混合验收
冻结项：...

| 节点 | 名称 | 目标 | 验收点 | 预计耗时 |
|---|---|---|---|---|
| TF-XXX-N01 | 节点名称 | 本节点要达成什么结果 | 怎样判断节点完成 | 低复杂度 / 中复杂度 / 高复杂度，或宽区间 |
| TF-XXX-N02 | 节点名称 | ... | ... | ... |

总预计耗时：粗粒度区间或复杂度等级。
请确认是否按以上清单执行。
```

## 2. 为什么要固定格式

1. 用户可以快速比较不同任务流的范围、目标和验收点。
2. 新会话接手时更容易恢复上下文。
3. 节点清单能直接映射到未来产品里的 WorkPackage / TaskTicket。
4. 避免模型每次根据表达习惯重排格式，造成阅读和执行成本。

## 3. Skill 更新同步规则

修改 `skills/*/SKILL.md` 时，必须同步检查：

```text
skills/<skill>/README.md
skills-README.md
docs/文档导航.md
docs/guides/* 或 docs/reports/*
交接说明或版本说明（如本轮涉及）
```

如果 `SKILL.md` 内容较新，但 README / 导航 / 版本说明没有同步，应判断为“配套文档同步缺口”，不能反向推断 skill 不是最新。

## 4. 与产品化的边界

本治理规则面向当前执行技能，不等同于最终产品 UI。产品化时应将内部术语转译为用户可理解概念：

| skill 概念 | 产品化表达 |
|---|---|
| taskflow | 项目推进计划 / 工作包流 |
| node | 可验收工作包 / 阶段任务 |
| pause gate | 待决策 / 阻塞 / 风险门禁 |
| evidence | 验证证据 / 交付产物 |
| visible-summary | 阶段汇总 / 进展报告 |

## 5. 验收标准

后续 taskflow 输出合格的最低标准：

1. 启动清单使用固定表格；
2. 节点目标和验收点不为空；
3. 节点完成后最终回复包含完整生命周期日志；
4. 涉及前端/UI 的节点提供截图或说明无法截图原因；
5. 无法精确计时时明确写“未精确计时”；
6. 修改 skill 时同步配套文档。
