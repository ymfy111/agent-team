# task / taskflow v0.6 设计参考

> 本文记录 task v0.5.3 / taskflow v0.6 的当前规则，用于智能软件工厂设计参考。它不是普通用户功能说明，也不是 OpenCode 专用版。

## 触发口径

- `任务执行`：单任务标准模式；
- `任务执行 高质量`：单任务高质量模式；
- `任务流执行`：多任务流标准模式；
- `任务流执行 高质量`：多任务流高质量模式。

## 核心边界

- task 是单任务质量闭环，不显示任务流进度图；
- taskflow 是任务流编排，才显示任务流节点进度；
- taskflow 调用 task 时，task 进入 managed 模式，不逐项中断用户确认。

## taskflow v0.6 关键规则

1. 先选 SOW，再生成任务流；
2. 节点必须是工作包级颗粒度，默认 2-5 个节点；
3. 读取资料、识别口径、分级排序、输出建议、打包、检查等默认属于 task 内部步骤；
4. 计划中的每个节点必须有开始和完成输出；
5. 如果节点需要合并，必须先说明合并原因；
6. 可使用临时过程文件记录节点耗时，完成统计后删除；
7. 无可靠计时不得输出具体实际耗时；
8. 暂停可恢复，退出表示不建议继续；
9. 完成总结必须自评：节点颗粒度、进度展示、计时记录。

## 与智能工厂的关系

- taskflow 是单智能体串行任务流；
- 智能工厂是多智能体协同系统；
- taskflow 可作为任务清单、质量门禁和待决策恢复机制的轻量参考；
- 智能工厂还需要并行调度、资源管理、冲突处理、审查队列和 Runtime 状态同步。
