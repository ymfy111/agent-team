# task / taskflow 技能使用参考 v0.4.1

> 本文档记录 `task v0.5.1` 与 `taskflow v0.4.1` 的最新经验，用作智能软件工厂设计和后续执行流程的参考。它不是面向普通业务用户的产品功能说明，而是对“任务清单驱动 + 单任务质量闭环 + 暂停/恢复门禁”的工作机制沉淀。

## 1. 技能定位

| 技能 | 中文触发 | 定位 | 当前版本 |
|---|---|---|---|
| `task` | `任务执行` / `任务执行 高质量` | 单任务质量闭环 | v0.5.1 |
| `taskflow` | `任务流执行` / `任务流执行 高质量` | 多任务工作包编排，调用 `task(managed)` | v0.4.1 |

两者关系：

```text
taskflow 管阶段 / 工作包 / 顺序 / 暂停门禁
task 管一个具体任务的计划、执行、验证、评审、修复和交付
```

## 2. 关键边界修复

v0.4.1 最重要的修复是：

```text
任务执行 / 任务执行 高质量
→ 只能使用 task 的单任务格式
→ 显示任务计划、执行步骤、评审轮次、修复记录、交付总结
→ 不得显示“任务流进度”节点图

任务流执行 / 任务流执行 高质量
→ 才能使用 taskflow 的任务流节点进度图
```

这个边界对智能软件工厂也有参考价值：单个任务闭环和跨任务编排必须分层，否则会导致执行状态混乱。

## 3. taskflow 的 SOW 选择机制

当用户只说 `任务流执行`，但没有明确任务清单时，taskflow 不应直接生成完整流程，而应先列出 3-6 个候选 SOW：

```text
候选 SOW：
[1] 文档收口
[2] 原型验收
[3] 交接包整理
[4] 技能经验同步
```

用户选择 SOW 后，taskflow 再生成正式任务流计划。

对应智能工厂设计：这类似项目启动前先确认本次工作包范围，再进入任务拆解，而不是由主智能体直接假设全部范围。

## 4. taskflow 节点颗粒度规则

任务流节点应该是“工作包”，不是微步骤。

适合作为 taskflow 节点：

- 文档一致性收口；
- 原型演示路径收口；
- QA 验收；
- 最终交接包整理；
- 技能经验同步。

不适合作为 taskflow 节点：

- 改一个标题；
- 补一个链接；
- 更新 manifest；
- 截图一次；
- 检查 ZIP 文件数量。

这些应放入某个 `task` 内部作为执行步骤。

对应智能工厂设计：项目任务单也应避免过度拆碎。任务单应有独立目标、产物、验收价值或门禁价值。

## 5. 进度可观测与真实计时

每个 taskflow 节点开始和完成时都应输出简洁进度，不应只展示第一步后直接跳到全部完成。

```text
任务流进度
[✓] 01 文档收口
[▶] 02 原型验收
[ ] 03 交接包整理

当前：02 原型验收
调用：task(managed)
```

计时规则：

- 有真实节点计时，才输出实际耗时；
- 无精确计时，必须写“未精确计时”；
- 不得输出没有依据的“约 24 分钟”等看似具体的耗时；
- 可注明“用户界面显示耗时”作为参考，但不能替代节点级计时。

对应智能工厂设计：长任务的状态、耗时和产物需要可观测，不能只依赖智能体口头总结。

## 6. 暂停、恢复、退出

### 暂停：可恢复

暂停不是失败，而是等待用户确认、补充信息或做业务取舍。

```text
任务流暂停
当前位置：03 xxx
暂停原因：需要用户确认技术路线
已完成节点：01、02
未完成节点：03、04
需要用户提供：选择 A / B
```

用户补充后可恢复：

```text
任务流恢复
恢复点：03 xxx
继续方式：按原计划继续 / 调整后继续
```

### 退出：不可继续或不建议继续

退出用于基线损坏、工具不可用、关键依赖长期缺失、质量多轮不收敛等情况。

对应智能工厂设计：暂停机制可作为“待决策 / 阻塞 / 需补充信息”的轻量参考；退出机制对应流程终止、回退安全基线或重新规划。

## 7. 单智能体串行与智能工厂多智能体并行的边界

`taskflow` 是一个智能体依赖技能完成串行长程任务。智能工厂是多个智能体协作的产品化系统。

| 维度 | taskflow | 智能软件工厂 |
|---|---|---|
| 执行主体 | 单智能体 | 多智能体 / 多数字员工 |
| 执行方式 | 串行 | 串行 + 并行 |
| 状态复杂度 | 低 | 高 |
| 冲突处理 | 少 | 多工作区 / 多 Runtime 冲突 |
| 暂停机制 | 技能级暂停 | 产品级待决策工作台 |
| 质量门禁 | task 评审 | 交付审查岗 / 任务审查记录 |

因此，task/taskflow 只能作为智能工厂的轻量参考模型，不能直接等同于完整智能工厂架构。

## 8. 对后续实现的参考

- taskflow 的 SOW 阶段可映射为项目阶段范围确认；
- taskflow 节点颗粒度规则可映射为任务单拆分原则；
- task(managed) 可映射为系统调度执行岗完成具体任务；
- 暂停/恢复可映射为待决策工作台；
- 计时和进度可观测可映射为项目健康和任务推进指标；
- 评审追踪可映射为交付审查记录。
