# task / taskflow 技能实践参考

> 版本：v0.2 参考稿  
> 用途：记录 `task` / `taskflow` 技能经验与智能软件工厂设计理念的对应关系。  
> 注意：本文是设计参考，不代表普通用户界面必须暴露这些术语。

## 1. 技能定位

| 技能 | 中文触发 | 定位 |
|---|---|---|
| task | 任务执行 / 任务执行 高质量 | 单任务质量闭环 |
| taskflow | 任务流执行 / 任务流执行 高质量 | 长程任务清单编排，调用 task |

## 2. 两层机制

```text
taskflow 负责：读任务清单、选下一项、控制顺序、更新状态、阶段汇总。
task 负责：一个任务的计划、执行、验证、评审、修复、交付。
```

## 3. direct / managed 模式

| 模式 | 说明 | 对应产品语义 |
|---|---|---|
| task direct | 用户直接调用任务执行，执行前必须确认计划 | 用户发起单任务 |
| task managed | taskflow 调用 task，不逐项等待用户确认 | 长程任务中的子任务执行 |

## 4. 与智能工厂设计映射

| 技能经验 | 智能工厂映射 |
|---|---|
| taskflow | 协同规划岗 / 主智能体维护任务流 |
| task | 单个 TaskTicket 的质量闭环 |
| managed task | 被编排的无人值守子任务 |
| 暂停门禁 | 待决策、阻塞、质量不收敛 |
| 评审追踪表 | ReviewRecord / QualityGate |
| 前后截图对比 | QA Artifact |
| 任务流进度图 | 项目 / 任务流进度视图 |

## 5. 对产品化的启发

后续智能软件工厂不必一次性实现完整状态机，可以按以下路径演进：

```text
1. 结构化 Markdown 任务流清单。
2. 单任务质量闭环记录。
3. 暂停门禁与待决策映射。
4. 评审追踪与 QA Artifact 持久化。
5. 任务流进度视图。
6. 程序状态机逐步接管常规流转。
```

## 6. UI 边界

普通用户界面不应直接暴露 `taskflow`、`managed`、TaskEvent、状态机等内部术语。UI 应稳定呈现：

```text
项目推进
岗位产出
任务状态
审查意见
待决策
下一步动作
```

底层可从主智能体任务清单逐步演进到程序状态机，用户心智尽量不变。


## 7. v0.2 补充：暂停、恢复与退出

`taskflow` 的暂停机制可作为智能工厂待决策机制的轻量参考。

### 7.1 暂停

暂停表示任务流暂时无法继续，需要用户确认、补充资料或处理业务取舍。暂停时必须说明：

- 当前节点；
- 暂停原因；
- 已完成节点；
- 未完成节点；
- 需要用户补充的信息；
- 恢复建议。

### 7.2 恢复

用户补充后，应支持从暂停点继续执行，而不是重新执行整个任务流。

```text
任务流暂停 → 用户补充信息 → 从暂停节点恢复 → 继续执行 / 重规划 / 缩小范围
```

### 7.3 退出

退出表示当前任务流不应继续推进。典型原因包括：质量长期不收敛、关键依赖缺失、工具不可用、继续执行会破坏安全基线、原计划方向错误。

退出时必须明确：中断位置、原因、已完成节点、未完成节点、已生成产物、风险和下一步建议。

## 8. 与智能工厂的本质区别

`taskflow` 是一个智能体依赖技能、结构化任务清单和质量门禁完成长程任务，默认串行推进。

智能工厂是多智能体协同系统，需要处理：

- 多数字员工并行执行；
- 多团队协同；
- 任务冲突和资源抢占；
- RuntimeHost / RuntimeNode 调度；
- 审查队列与返工队列；
- 跨项目、跨团队依赖；
- 多智能体反馈汇总与重规划。

因此，`taskflow` 适合作为流程语义、暂停/恢复、评审追踪和质量门禁的参考，但不等同于智能工厂完整编排能力。
